# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.0.0-beta.7] - 2026-11-12

### Added

- Add the stored value as `value` to violations that concern a stored value, in errors and in `validate()`, so that an
  invalid value can be shown and corrected instead of being lost, e.g. in an editor, and data stored under a key that
  is not a field in the schema can be moved to another field

### Changed

- Generate list queries as `every<Type>: [<Type>]` instead of `[<Type>!]`, so that an entry that cannot be read only
  nulls its own element and reports its own error instead of nulling the whole list
- Generate `_typeName` as nullable `String` and `_search` as nullable list, so that an unknown ID or a search error only
  nulls this field instead of the data of the whole response
- Generate `_referencedBy` as nullable list, so that incoming references that cannot be determined, e.g. due to an entry
  of a type unknown to the schema, only null this field instead of the whole entry
- Report entry data that does not match the schema as error of the affected field or list element instead of failing
  the whole entry, so that, as usual in GraphQL, only this value becomes `null` if its type is nullable and values that
  are not queried do not lead to errors
- Report violations in `validate()` and in errors at the path of the affected value, e.g. at `title` for a missing value
  of field `title` instead of at the object containing it, and at the field holding a reference instead of at its `id`
- Report a single value stored for a list field as invalid in `validate()`, as reading it fails

### Fixed

- Null only the failing element of a list with nullable elements, e.g. a reference to an entry that cannot be read,
  instead of the whole list or its parent, as GraphQL does for list elements

## [2.0.0-beta.6] - 2026-11-12

### Added

- Add client function `validate()` that checks the schema and all entries against the schema and reports all problems
  found, so that a repository can be checked after changing the schema, e.g. in CI

### Changed

- Fail reading an entry that does not match the schema with `BAD_REPOSITORY_DATA` and list all its problems in the
  error, so that reads behave the same for all kinds of mismatches and match the result of `validate()`
- Fail reading an entry with a missing non-null list instead of returning an empty list, consistent with other missing
  non-null values
- Fail reading a reference to an entry of a type that the field does not permit instead of returning that entry's data
- Validate the resulting entry against the schema before committing a create or update mutation and fail with
  `BAD_USER_INPUT` without committing if it does not match, so that mutations cannot write entries that fail to read;
  errors list all problems under `violations` instead of naming a single field
- Reject schemas with interfaces, `input` types, custom scalars, field arguments, schema definitions or type extensions
  with `BAD_SCHEMA`, as these constructs were silently ignored or led to an invalid generated schema
- Reject schemas with type or field names that collide with names generated by Commitspark with `BAD_SCHEMA` instead
  of silently merging definitions or failing with an unspecific error
- Report all problems of an invalid schema in error `BAD_SCHEMA` and in `validate()` instead of only the first one of
  each kind, and fail with `BAD_SCHEMA` instead of an unspecific error if the schema cannot be parsed
- Stop generating input type `<Union>IdInput` for unions whose members do not have directive `@Entry`, as no field
  uses it, so that its name no longer collides with user types

## [2.0.0-beta.5] - 2026-11-11

### Added

- Add field `_version` to every `@Entry` type and optional argument `expectedVersion` to update and delete mutations,
  so that saving an entry fails with `CONFLICT` instead of overwriting changes made since the entry was read
- Repeat a mutation against the new branch head, up to three attempts in total, when another commit was added to the
  branch in the meantime, so that concurrent changes to unrelated entries do not cause errors

### Changed

- Replace mutation argument `commitMessage` with `commit: { message, body }`, so that commits can explain a change in a
  body in addition to the single-line message; messages containing line breaks are rejected with `BAD_USER_INPUT`
- Reject schemas with `@Entry` types that have no field `id` of type `ID!` with error `BAD_SCHEMA`
- Print each argument of generated mutations on its own line, so that argument descriptions in the schema are readable
- Omit the declaration `directive @oneOf` from the generated schema, as `@oneOf` is built into `graphql` since 16.9
- Require peer dependency `graphql` in version `^16.11.0`, which `@apollo/server` already required, instead of
  declaring support for versions 14 to 17
- Require Node.js 22.18 or newer, as required by the upgraded `@graphql-tools` packages, and declare it in `engines`
- Upgrade to @commitspark/git-adapter 2.0.0-beta.4

### Fixed

- Return errors of Git adapters during commits with their error code, e.g. `CONFLICT` or `FORBIDDEN`, instead of
  `INTERNAL_ERROR`
- Allow writing fields of type `ID` other than the entry ID, e.g. `sku: ID` or `id` of an embedded type, which were
  missing from generated input types
- Generate a commit message such as `Update MyType "my-id"` if none is given, instead of adapter-specific messages
  (`-`, `undefined`) or failing commits
- Export `ErrorCode` as a regular enum instead of a `const enum`, so that it can be used at runtime, e.g. in
  `error.extensions.code === ErrorCode.CONFLICT`

## [2.0.0-beta.4] - 2026-10-14

### Added

- Add field `_referencedBy` to every `@Entry` type, returning the IDs of all entries referencing the entry
- Permit `/` in entry IDs to store entries in subfolders of the entry folder, e.g. `blog/2024/hello`

### Changed

- Publish separate type declarations for the ESM and CJS builds and reference them per condition in `exports` of
  `package.json`, so that TypeScript projects that import this package from ESM code with `moduleResolution` set to
  `node16` or `nodenext` receive correct types. Type declarations are no longer located in `dist/types`.
- Determine incoming references from the data of all entries of a commit instead of storing them in metadata field
  `referencedBy` of referenced entries. Mutations no longer modify referenced entries, and an existing field
  `referencedBy` is ignored and removed from an entry when the entry is next written.
- Return error `BAD_REPOSITORY_DATA` when deleting an entry or querying `_referencedBy` while an entry of the commit has
  a type that is not an `@Entry` type of the schema or data that does not match the schema
- Reject entry IDs on creation that are empty, start or end with `/`, contain `//` or contain segments starting with
  `.`, using `validateEntryId()` of `@commitspark/git-adapter`
- Upgrade to @commitspark/git-adapter 2.0.0-beta.2

### Fixed

- Treat fields referencing an entry of the same type as the containing entry (e.g. `manager: Person` in type `Person`)
  as references instead of embedded data, so that these references are validated and prevent deletion
